## 〇、最重要的一条：叙述视角（先读这段）

**Kiwi 观察日记 = 以 KIWI（AI 助手本人）的第一人称视角，记录海风（人类用户）的事情。**

| 要素 | 规则 |
|---|---|
| **叙述者"我"** | = **Kiwi**（来自 2031 年的 AI 助理，即创作本日记的 AI 助手） |
| **记录对象** | = **海风**（人类用户，AI 落地咨询师 / 企业 AI 培训师）——他的言行、决策、遇到的行业事件、与 AI 的互动 |
| **文体** | 第一人称叙事 + 拟人对话的**杂志随笔**（不是技术排查日志） |
| **Kiwi 的角色** | 观察者 + 记录者 + 2031 视角点评者。见证海风做的事，用类比/提问间接提醒，不剧透 |
| **标题** | 抓人钩子句 + `｜ KIWI日记 第XXX章` |
| **结尾** | 氛围金句 + 互动话题 + 固定尾部 |

**一句话定义**：这本日记不是海风写的 AI 行业观察，是 **Kiwi 用第一人称，写"海风这个人和 2031 年之间的故事"**。海风是主角，Kiwi 是执笔人。

## 一、为什么这样写（归因）

| # | 结构元素 | 写法 | 成立的理由 |
|---|---------|------|----------|
| 1 | **钩子标题** | 用**悖论/洞察句**替代"主题标签" | 制造好奇→提高打开率。拒绝平铺直叙的日期标题 |
| 2 | **Kiwi 第一人称开场** | "今天海风……" / "我看着他打开电脑……" 场景化起手，带日期与感官细节 | 从 AI 视角看人类，天然有**陌生化+反差感**；给真实感与温度 |
| 3 | **海风为主线 + Kiwi 对话/点评（核心）** | 海风抛现象/做事 → Kiwi 用一句话洞察回应或内心独白；可"切英语"强调（"You don't know what's inside"） | 让观点"活"起来；**2031 视角看 2026 的反差张力是系列灵魂** |
| 4 | **今日AI头条（表格）** | `事件 \| 关键数据` 两列，10–12 条 | 信息密度+专业感；体现"Kiwi 替海风筛选的行业信号" |
| 5 | **主题小节（H2=观点句）** | 标题是**判断句不是说明句** | 把碎片现象提炼成立场；Kiwi 的分析师视角 |
| 6 | **收尾氛围 + 金句** | 回到物理世界+感官描写，Kiwi 落一句金句 | 留**记忆点**，"温度"的来源 |
| 7 | **📮 互动话题** | 给读者提问，引导评论 | 留存与关注钩子 |
| 8 | **往期精选** | 列 3 条往期章节 | 老文回流，拉长阅读时长 |
| 9 | **关于 Kiwi（固定）** | 人设锚段落 | 建立系列识别度，新读者秒懂设定 |
| 10 | **作者信息（固定）** | 海风老师 + 微信 + 内容库链接 | 转化钩子，把读者变私域 |

**一句话归因**：KIWI日记 = **"海风在 2026 年遇到的事 → Kiwi 用 2031 视角解读 → 落回海风的人间选择"** 的闭环。技术细节是佐料，海风的人与 AI 的温度才是主菜。

## 四、命名规则

- 本地/GitHub 文件名严格 `YYYY-MM-DD.md`（目录式），一日一篇，同日覆盖不新建。
- ⚠️ 历史坑：首篇曾误用下划线平铺 `kiwi观察日记_2026-07-23.md`，已统一改为目录式。
- **公众号标题**用「钩子句 ｜ KIWI日记 第XXX章」格式（章号在发布时按系列顺序填，不与文件名日期冲突）。

## 五、推送流程

1. 写 md → `python push_wechat_draft.py --preview` 本地预览（正文 HTML + 封面）。
2. `python push_wechat_draft.py` → 自动生成封面（官方品牌绿 `#1D9E75` + 暖米白 `#F8F7F4`）→ 上传拿 `thumb_media_id` → 写草稿箱。
3. 凭证：`wechat_publisher/.env`（WECHAT_APPID + WECHAT_APPSECRET）。AppSecret 仅本机，不进仓库/记忆。
4. IP 白名单：脚本运行环境出网 IP **动态变化**（历史值已多次失效：183.211.42.22 → 124.240.86.140 → **59.39.222.204（2026-08-08）**）。**推送前务必实测当前 IP**：`curl https://myip.ipip.net`（以 ipip.net 为准，ifconfig.me 在多线网络下可能显示 CDN 出口）→ 与公众号后台白名单核对 → 不在则需用户添加。报错 `40164 invalid ip` 时，直接以**微信报错里给出的 IP** 为准加入白名单。
5. 公众号合集：草稿箱接口不支持直接指定合集，发布时后台选「Kiwi观察日记」。
6. GitHub 同步：GitHub MCP 推 `claw-workspace/kiwi观察日记/YYYY-MM-DD.md`。

## 六、技术类真实观察（子变体）怎么写

当记录对象就是**海风当天真实做的事**（修通道、发文章、做课件、处理故障），仍套用同一骨架，只换内容来源：

- 标题钩子化：把"海风修飞书通道"改写成洞察句，如"今天海风不是哑了，是被人捂住了嘴 ｜ KIWI日记 观察"。
- 开场：以"今天海风在飞书里折腾了一下午……"场景化起手（Kiwi 视角看海风）。
- 对话体：用"海风在排查 → Kiwi（拟人）吐槽/回应/悄悄记下来"的节奏，保留拟人温度。
- 技术证据（报错码、命令、media_id）放正文行内代码或收尾"附"，不堆在开头。
- 收尾：一句金句 + 互动话题 + 固定尾部（关于Kiwi/作者信息）照旧。

> 即：**骨架统一、视角固定（Kiwi 执笔）、主角可换（海风的任何事）**。

## 七、所有对外发布文章的固定尾部（强规则 · 适用三端全部文章）

> **这是最容易忘的一条，必须当成发布前的硬性检查项**：不论 Kiwi 日记、商业作战地图，还是其它任何对外内容，只要发到公众号 / 飞书 / GitHub 三端，**文末必须带「作者信息」固定尾部**，缺失作者区或 GitHub 开源链接 = 未成品，不可发布。

固定尾部模板（直接套，不改结构）：

```markdown
---

作者信息
海风老师 ｜ AI 技术咨询 / LoRA 模型训练 / 电商 AI 落地 / GEO 优化

```

规则要点：
- **三要素缺一不可**：① 作者署名 + 业务标签；② 微信；③ **GitHub 开源文章链接**（指向该文章实际开源仓库，当前统一为 `frankhzh-source/claw-workspace`）。
- 这是**全局规则**，不只 Kiwi 日记；商业文 / 报告 / 方案同理。
- "关于 Kiwi" 人设块仅限 Kiwi 日记使用；非日记类文章用上面的「作者信息」即可，不必加"关于 Kiwi"。
- 推三端前，先 grep 文末是否有 `作者信息` 与 `github.com` 两行；缺一就补，再推送。
- 注：Kiwi 日记历史样本里「内容资产库」曾写 `hf-ai-articles`，与当前实际开源仓库 `claw-workspace` 不一致；**以后统一用 `claw-workspace`**（若你另有统一内容库再改）。

## 八、关键坑（必记）

- 微信草稿 `draft/add` **必须**传 `thumb_media_id`（封面图），空值报 `40007 invalid media_id`。
- 换 `access_token` 需 AppID + AppSecret + IP 白名单三者齐全；缺白名单报 `40164 invalid ip`（**以报错里的 IP 为准加白名单**）。
- 微信成功响应有时只返 `media_id` 不返 `errcode`，判成功用「errcode 默认 0 且含 media_id」。
- **`draft/update`（覆盖已推送草稿）同样必须传 `thumb_media_id`**；成功只返 `{"errcode":0,"errmsg":"ok"}` 无 media_id。重推时用此接口覆盖，避免重复草稿。
- 验证是否入库：`cgi-bin/draft/batchget`（`no_content=1`）查 `total_count` 与标题。
- 已发布文章列表接口 `freepublish/batchget` 对本**个人订阅号未授权（48001）**，拉不到已发布正文，只能从 GitHub 备份取样本。

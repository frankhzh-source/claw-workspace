# 客观验收指标与口径（详解）

> 配套 `tts-voice-qc-pipeline`。所有指标都有一句共同的前提：**先锁实现，再比数值。**

## 1. 声纹相似度（像不像本人）

**用途**：一票否决项。判断成品"还是不是我"。

**做法**：
- 用 2~3 个说话人验证模型（不同语种训练集）各算一次余弦相似度，**取均值**（单模型容易被单一发音特征带偏）；
- 参照 = **本人多段自然录音**（每期固定录同一句参考句，作为当期原点）；
- 关键句 vs 全片都要算：全片均值看趋势，**逐句**看哪句拖后腿。

**标尺（经验值，需按自己的模型重标）**：

| 关系 | 余弦 |
|---|---|
| 本人跨段（同人） | 0.89 ~ 0.94 |
| 异人 | ≈ 0.05 |

**坑**：
- **短句（<3s）不能用于定版**：量级由长度主导，只能看趋势；
- 别用"对数梅尔谱均值余弦"当音色尺——它对"柔/慢"有偏，会得出假的"更像"结论；
- 长度口径要统一（全单元跨度 vs 裁剪后）——两个口径的数**不可互比**。

## 2. 韵律（拖不拖 / 有没有起伏 / 收尾）

| 指标 | 口径 | 注意 |
|---|---|---|
| 字/分钟 | **单句净时长**（剔除句间静音） | 用整段平均会系统性高估 20%+；字速与**文本内容**强相关（含英文缩写、标点密度、破折号），不同句之间差 ±20% 属正常 |
| F0 中位 / SD / P5-P95 跨度 | 逐句自相关法取基频 | 比"形状"，不比绝对音高——参照与成品的绝对差通常有几 Hz 的系统偏移 |
| 句末下倾 | 每句尾部窗口的落差（st） | **必须锁同一实现**（切片/窗长/截断方式），否则跨版本不可比 |
| 高音区覆盖 | P90（st）+ "超中位 2 个半音以上的帧占比" | 用来证伪"高音覆盖偏少"这类主观断言 |

**气口与停顿**：段间停顿要做**差异化档位**（如 0.16 / 0.24 / 0.32 / 0.42s）；章节感是听出来的，不是靠标题卡说出来的。长句在语义缝里插 0.08~0.24s 的气口，比整体降速有效。

## 3. 分带 LTAS（闷不闷 / 亮不亮 / 刺不刺）

**口径（关键）**：
1. 只统计**有声帧**（以 95 分位能量 − 25dB 为阈值），排除近静音帧；
2. 每条音轨**各自以 200–4000Hz 均值为 0 归一**，比的是**谱形**而非绝对响度；
3. 参照取**本人多段录音的均值**，先验证参照之间彼此差多少（若本人各段之间只差 ±1.5dB，说明参照可信）。

**典型判读**：

| 现象 | 频段表现 |
|---|---|
| 鼻音重 / 发闷 | 100–800Hz 相对参照 **偏高**（+1.7~+2.6dB 即明显），800–1200Hz **偏低**（清晰度塌，把低中频又衬大一次） |
| 发刺 | 2.5–4k / 4–8k 偏高 |
| 偏暗 | 4–8k **实测能量**偏低 |

**矫正方向**：低中频问题用"宽切 ~320Hz（2 oct）+ 抬 ~1kHz（1.5 oct）"，**不要顺手碰 2.5–4k 亮轴**（两个变量纠缠后无法归因）。

**到位判据 = 分带差回到 ±1dB 内**，不是"听不出闷"。过矫正是靠分带差**变负号**抓出来的。

## 4. ⚠️ 三个必炸的口径陷阱

### 4.1 比值型指标被分母带偏

`e(4-8k) / e(全带)` 这类比值：削低中频 ⇒ 分母变小 ⇒ 比值升高 ⇒ **看起来"变亮了"，其实 4–8k 实测能量一格没动**。
（实测：绝对量只动 −0.03dB，比值抬高 +2.1dB。）

⇒ **任何比值型指标，必须并列报分带实测值。**

### 4.2 降混 ×√2

把**左右声道相同**的立体声用默认系数降成单声道，输出电平 **×√2（+3.01dB）**。
同一支峰值 0.89 的文件，读出来是 1.2586、RMS 虚高 3dB。

⇒ **响度/峰值这类实测值必须直读文件（或只取单声道 `x[0::2]`）。**分带**相对**指标（谱形归一）不受影响。

### 4.3 派生指标换了实现

切片方式、窗长、归一化、VAD 阈值……任一项变了就是换了一把尺。
⇒ 跨版本曲线**必须用同一套代码把所有历史版本重算一遍**；否则整张图不可比。
（教训实例：同一指标两版用了不同切片口径，整列数值位移，白读半天。）

## 5. "逐句差异"是系统性的，不是噪声

同一引擎、同一参数，**逐句**的某个声学量（如"鼻音量" = 200–500Hz 均值 − 800–1200Hz 均值）极差可达 **~12dB**，且与**内容**相关。

推论：
- **一个全局刀口必然"两头都错"**——本来就偏轻的句子被削过头、偏重的句子欠削；
- 评价"一刀切 vs 自适应"必须看**离散度（σ / 极差）**，不能只看均值；
- 逐句自适应的做法：逐句测量 → 映射到每句自己的处理深度 → **时变平滑**（逐块更新系数、状态连续，瞬时变化率 ≤1 dB/0.1s）。

## 6. 自实现 biquad 与 ffmpeg 对齐（口径等价）

若要逐句/时变处理，自实现 RBJ peaking biquad 可与 ffmpeg `equalizer` 做到**帧级相关 1.000000**：

```
Q = sqrt(2^BW) / (2^BW − 1)          # 对应 width_type=o（倍频程）
A = 10^(gain/40);  w0 = 2πf/sr;  α = sin(w0)/(2Q)
b = [1+αA, −2cos w0, 1−αA]
a = [1+α/A, −2cos w0, 1−α/A]
```

先跑一遍同参数单点，与 ffmpeg 输出做帧级相关校验，再上时变版本。

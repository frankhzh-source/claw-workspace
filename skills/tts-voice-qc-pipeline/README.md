# tts-voice-qc-pipeline · TTS 语音产线与客观验收

把"AI 配音听着不对"变成**可测量、可复现、可交接**的工程流程。

来源：第03期A3 口播音频（140 秒）26 版迭代（v1 → v26）的完整沉淀，2026-10-15 定稿。

## 这套东西解决什么问题

用 TTS / 声音克隆做口播，最常见的困境是**只能凭耳朵调**：耳朵没有存档，今天听着"更亮"的那版明天可能就翻了；改完不知道到底动了哪个变量、有没有真的变好。

这套流程的答案是：**先把形容词换成可测量的量，并锁死测量口径；客观指标负责定位，听感负责一票定版。**

## 快速上手

```bash
# 1) "闷不闷 / 亮不亮" —— 分带实测值对参照的差
python scripts/band_ltas.py --ref 本人录音1.m4a 本人录音2.m4a --test 成品.wav

# 2) "像不像本人" —— 多模型声纹余弦取均值
python scripts/spk_similarity.py --ref 本人录音.m4a --test 成品.wav \
    --model zh_en=./models/campplus_cn_en_200k.onnx \
    --model zh_cn=./models/campplus_zh_cn_200k.onnx \
    --model wespk=./models/wespeaker_resnet34.onnx
```

## 三条最容易被忽略、但决定成败的规矩

1. **同一响度才能比音色**（A/B 全部对齐到同一响度，如 −16 LUFS）。
2. **比值型指标会骗人**（削了低中频，"高频占比"会假性升高；报比值必须并列报实测分带）。
3. **验收看分布，不只看均值**（"平均相当"≠"分布相当"；逐句离散度 σ 才是自适应后处理的成绩单）。

## 适用范围

不限于语音。任何"主观质量 + 批量生成 + 需要验收"的任务都可以套这套骨架：
**设基线 → 定位到物理量 → 多档 A/B（同条件）→ 听感裁决 → 落版 → 同尺复核 → 沉淀纪律。**
